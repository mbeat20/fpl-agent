# 15 — Team dashboard: squad view, instinct panel, unprompted weekly suggestion

**What to build:** A second view in the frontend (a simple tab/toggle in `App.tsx`, not a router — v1 is two views, not worth a new dependency) alongside the existing Ask flow, so the user has somewhere to land without typing a question first:

1. **Squad view** — the user's 15 players (name, position, club, price, ownership, form, injury status) and current gameweek, rendered from the existing `get_my_team` handler. Purely a read: no new backend logic, just a `GET` route wrapping `fpl_coach.tools.get_my_team.get_my_team(conn, MY_TEAM_ID)`.
2. **Instinct panel** — this gameweek's logged Instincts (issue 13's `get_instincts`), shown as a list, plus a small dedicated input for logging a new one. Today the *only* way in is typing `remember: thinking X` into the Ask box; this adds a `GET` route wrapping `get_instincts` and reuses the existing `POST /recommendations` remember-short-circuit for writes (no new write path — the input just prepends `remember: ` if the user doesn't type it themselves, same classification via `is_instinct`).
3. **Unprompted weekly suggestion** — a Recommendation generated without the user asking anything, shown on the dashboard. Per ADR-0002 (on-demand ingestion, no scheduler for v1), this must NOT be a cron job — it's generated synchronously, on-demand, the same way ingestion already is. A `GET /team/suggestion` route: if a cached suggestion exists for the *current* gameweek, return it; otherwise call `reasoning.reason()` once with a fixed prompt ("Anything I should know or consider this gameweek?", all existing tools available) and persist the result before returning it. Same shape as any other Recommendation — logged via the existing `log_recommendation` (issue 10) so it's eligible for outcome tracking like any other pick. Regenerates only when the gameweek advances (new `current_gameweek`), not on every page load — one Claude call per gameweek, not one per visit.

## Open questions (resolved)

- **`TransferPlan` vs `Recommendation`-only for the unprompted suggestion:** went with allowing either, same union (`Recommendation | TransferPlan`) `/recommendations` already returns, rather than the original "`Recommendation` only" lean. Restricting it would mean threading a new flag through `ClaudeReasoning.reason()`/the `Reasoning` protocol to conditionally withhold `submit_plan` (`claude.py` currently always offers both) — real surface area for a case `_SUGGESTION_PROMPT`'s single-gameweek framing already nudges the right way in practice. Frontend handles either via the existing `isTransferPlan` check, no new component.
- **Squad view fields:** `get_my_team`'s existing fields (name, position, club, price, ownership, form, status, news) were sufficient — no new ingestion needed.
