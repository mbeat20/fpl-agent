# 13 — Early instinct log

**What to build:** A gameweek-scoped Instinct log, distinct from the Preferences file (issue 04). The user logs an early-week transfer or captaincy thought (e.g. "thinking Rogers → Enzo"), same "remember: X" phrasing as a Preference but routed to a different destination based on whether it reads as a standing rule vs. a specific, dated decision. When the user later asks about that same player/decision within the same gameweek, the AI pulls in the original Instinct alongside its current Recommendation and prompts the user to reconcile: has their thinking genuinely evolved, or are they chasing a bandwagon? Instincts are discarded once that gameweek's deadline passes — they never accumulate like Preferences do.

**Blocked by:** 01 — Backend walking skeleton, 04 — Preferences file

**Status:** done

- [x] An Instinct can be logged ("remember: thinking Rogers to Enzo") and is tagged to the current gameweek
- [x] Asking about a transfer/captaincy decision later that gameweek surfaces the matching Instinct (if any) alongside the current Recommendation
- [x] The AI's response prompts the user to say whether their reasoning changed, rather than silently overriding the Instinct
- [x] Instincts are scoped to a single gameweek — a new gameweek starts with no leftover Instincts from the previous one
- [x] Logging an Instinct never writes to `preferences.md` — the two destinations stay separate despite the shared "remember: X" phrasing

## Comments

**2026-08-18:** Routing "remember: X" between Preference and Instinct is deterministic, not Claude-classified: `fpl_coach/instincts.py`'s `is_instinct()` checks whether the remembered text starts with "thinking" (case-insensitive) — CONTEXT.md's own Instinct example ("thinking Rogers → Enzo") already uses that exact marker, so it's a natural, regex-based split consistent with ADR-0010's "no extraction pipeline" stance for the sibling Preference concept. `POST /recommendations`'s existing `remember:` short-circuit now branches on `is_instinct()` before ever calling `append_preference`.

Gameweek scoping needed a persisted "current gameweek" concept that didn't exist anywhere before this ticket — `run_ingestion` (issue 03) resolves it internally via `_current_gameweek(bootstrap["events"])` but never persisted it. Added `gameweek_state`, one row per team (keyed by `team_id`, not a global singleton), upserted by `run_ingestion` right after it resolves the gameweek. Instinct logging/reading both read this table rather than calling the live FPL API themselves, keeping the `remember:` short-circuit's existing DB-only, no-wasted-Claude-call character. Deliberately keyed by `team_id` rather than a single global row: a global singleton would mean `test_ingestion.py`'s fake-bootstrap ingestion (`TEST_TEAM_ID`) permanently clobbers the *real* team's (`MY_TEAM_ID`) gameweek on every test run — the exact same class of shared-live-DB pollution bug found in issue 08 (`run_creator_ingestion` writing into the real `@FPLGeneral` creator). Keying by `team_id` plus `ON DELETE CASCADE` from `teams` means test cleanup (`DELETE FROM teams WHERE id = TEST_TEAM_ID`) automatically removes the test's `gameweek_state`/`instincts` rows too, with no separate teardown code needed — same convention already used for `creators -> creator_content`.

AC4 ("no leftover Instincts once the gameweek moves on") is enforced two ways: `get_instincts` only ever selects rows matching `gameweek_state`'s *current* row for that team (so a stale row is simply invisible even if not yet deleted), and `run_ingestion` also purges `DELETE FROM instincts WHERE team_id = %s AND gameweek <> %s` on every refresh, so old rows don't linger indefinitely either.

**2026-08-18 correction (found while building issue 10):** the purge line above was dead code from the day it was written, and AC4 held by accident, not by that mechanism. `run_ingestion` did `DELETE FROM teams WHERE id = %s` then re-`INSERT`ed it every cycle — since `gameweek_state`/`instincts` are FK'd to `teams(id) ON DELETE CASCADE`, that delete silently wiped **every** Instinct, current-gameweek ones included, before the purge query ever ran against an already-empty table. No test caught it because every test that seeded an Instinct did so *after* the fixture created the team, never *before* a `run_ingestion` call — issue 10's outcome-logging table hit the same cascade and made it impossible to ignore (outcome history requires the row to survive the next ingestion cycle, which it never did). Fixed in issue 10 by upserting the `teams` row (`ON CONFLICT (id) DO UPDATE`) instead of delete+insert, with `players` now wholesale-replaced via its own explicit `DELETE FROM players WHERE team_id = %s` rather than piggybacking on the `teams` cascade. `test_ingestion.py` now has `test_run_ingestion_preserves_a_same_gameweek_instinct` / `test_run_ingestion_purges_a_stale_gameweek_instinct` proving the purge line is live for the first time.

Surfacing + reconciliation-prompting (AC2, AC3) is entirely prompt-engineered, not code-enforced — same pattern as issues 07/08's evidence/risks framing. `get_instincts`'s tool description explicitly instructs Claude to quote a relevant Instinct verbatim and ask whether the user's thinking has genuinely evolved or whether they're chasing a bandwagon, "never silently override it and never silently just agree with it." `Instinct` results deliberately do NOT feed `_record_known_players` (reasoning/claude.py) — an Instinct is the user's own free-text note, not a structured player pick, so it doesn't need to (and shouldn't) widen `submit_recommendation`'s valid-pick enum the way issue 08's `PriceChangePredictions` did.

Verified at three layers: unit tests (`test_instincts.py`: `is_instinct` classification, `current_gameweek`/`log_instinct` behavior including the "no gameweek known yet" error path; `test_get_instincts.py`: gameweek-scoped filtering, confirming a prior-gameweek row is excluded) plus a Seam-1 route test (`test_recommendations.py`) proving `remember: thinking ...` lands in `instincts` and never in `preferences.md`. A Seam-2 integration test (`test_claude_surfaces_a_relevant_instinct_and_prompts_reconciliation`) seeds an Instinct whose text asks Claude to echo a distinctive tag when it uses the note (same determinism trick issue 04's Preference-framing test uses) — passes, confirming real Claude actually calls `get_instincts`, quotes the note, and names both players. Then smoke-tested over live HTTP against the running dev server: `remember: thinking Haaland over Salah for captain this week` correctly wrote an `instincts` row and left `preferences.md` untouched; a follow-up "Who should I captain this week?" came back quoting the exact Instinct text with its logged date and asking "has your thinking genuinely evolved... or are you just reconfirming a bandwagon take" — before picking Haaland anyway with that context folded into both evidence and risks. Cleaned up the fabricated `gameweek_state`/`instincts` rows afterward, same as issue 08's temporary `fpl_players` seed. Full non-integration suite: 71 passed, 9 deselected. Full integration suite: 7 passed.
